# Retained iteration demonstrations

`just iteration-feedback` allocates a new immutable scoped run and preserves
synthetic policy, hardware and rejected-publication evidence. It does not alter
reviewed configuration or publish acceptance. `--feedback-owner ACCEPTED_RUN`
also rechecks and links that accepted run's mandatory feedback: uncovered keys,
transient faults, missing/incomplete evidence and checkpoint controls. The
standalone demonstration verdict never substitutes for a real-ROM increment.

The session policy driver calls the public Session operation seam using explicit
symbolic external results. It retains default-one/count-two stopping, an already
satisfied target, crossing a target, explicit stop and publication refusal. Its
reports say “session policy simulation; acceptance not certified.” Successful
symbolic publication events are policy input, with production accepted count 0.

The release `iteration-probe` uses a literal synthetic cartridge, real production
emitted store, actual Subject/Reference fetch/PC execution and a state-dependent
faulty body. An early 65-instruction window passes; the same key's later execution
fails at instruction 86. Cold failed-frame localization retains instruction and
bus mismatch snapshots even though paired-cache next-frame validation rejects
the candidate. Correct emitted predecessor and disabled-key controls both pass
through the identical 87-instruction interval. ROM/input/emitted source, executable
and report identities remain with the evidence. The probe is nonaccepting.

Three distinct immutable failed policy candidates feed real experiment-history
machinery with one stable unresolved increment and predecessor. No observations
are invented to reset novelty; the streak is 1, 2, 3 and only the third produces
a decision. A real production `accept` command rejects the private incomplete
candidate and preserves the private pointer's exact bytes. These policy failures
explicitly make no claim that commercial frame parity executed.

`python3 tools/iteration_demonstrations.py verify --run RUN` checks the captured
source, sealed owned artifacts, process origins, retained policy state, literal
hardware assertions, failed candidate/history lineage and unchanged pointer
digests. Commercial source and accepted-state evidence remain separate. The
final integrated readiness refresh and default-one real session also require
all mandatory checks, cold 18,000-frame generated parity, changed-key and focused
coverage, legitimate independent reuse and positive comparable execution gain.
