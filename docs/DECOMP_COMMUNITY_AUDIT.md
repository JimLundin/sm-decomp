# Current Super Metroid high-level source community audit

Inspected **2026-10-10**, using upstream Git refs, commit objects, source, GitHub PR pages and repository-search results. This extends [DECOMP_PROJECT_COMPARISON.md](DECOMP_PROJECT_COMPARISON.md) and [DECOMP_SOURCES.md](DECOMP_SOURCES.md). No project was built, no replay was run, and no external message was sent. Clones, fetched refs, PR HTML and selected diffs are retained locally under `out/research/community/`; they are research evidence, not proposed dependency imports.

## Recommendation

Retain **snesrev/sm `578f90b3...` as the pinned C oracle candidate**, with **testyourmine/sm_rewrite `52378738...` for readability changes**. Add upstream **PR #50** to the immediate correctness review: it fixes a specific Kraid scratch-memory dependency removed by an earlier cleanup. Add rewrite **PR #8** and **aric-davison's `RL-env` branch** to the replay-harness review. These are substantive findings beyond the old main-branch snapshot, but none establishes a tested replacement oracle here.

The earlier comparison omitted **[MrJackSpade/SuperMetroidDecomp](https://github.com/MrJackSpade/SuperMetroidDecomp)**, an actively developed C# source port. It deserves a focused architectural and testing review before designing readable Rust: its explicit domain identities, decoded program catalogs, import/gameplay separation and input-only replay tooling directly address the proposed pivot. It is a useful reference to read. **No project-level copying license was found in its inspected tree**, and its status documents disagree; do not silently substitute it for the MIT C import source or claim this audit proved its full-game correctness.

No separate high-level Rust gameplay port was identified in the bounded searches below. That is a discovery result, not proof that none exists.

## New active high-level candidate: C# source port

**MrJackSpade/SuperMetroidDecomp `main`** was pinned during inspection to **`216f3a1d38c2e9d82ec9c0e626a35415b74d47c9`**, committed **2026-10-10 15:58:31 UTC**. It has release tags through **`v0.5.0`**, `6d9b96526ee535bfb51cacef7ad9b127eb4596b6`, committed **2026-10-10 08:07:59 UTC**. Later upstream work may advance this fast-moving snapshot.

This is substantive high-level game source. [Morph-ball movement](https://github.com/MrJackSpade/SuperMetroidDecomp/blob/216f3a1d38c2e9d82ec9c0e626a35415b74d47c9/csharp/src/SuperMetroid.Core/Game/SamusMorphBallMovement.cs) keeps original bank-$90 entry points and fixed-point collision semantics while exposing named state and operations. Recent commits type [enemy definitions](https://github.com/MrJackSpade/SuperMetroidDecomp/commit/ef19c76acfbedce1e484912f65089f765f044371), [cinematic instruction words](https://github.com/MrJackSpade/SuperMetroidDecomp/commit/45dde7f3f0eaaff9e69b80bed723119ec4807b08), and [map-sprite identities](https://github.com/MrJackSpade/SuperMetroidDecomp/commit/216f3a1d38c2e9d82ec9c0e626a35415b74d47c9). These provide relevant examples for readable Rust domains and closed instruction dispatch.

The [developer guide at the pin](https://github.com/MrJackSpade/SuperMetroidDecomp/blob/216f3a1d38c2e9d82ec9c0e626a35415b74d47c9/csharp/README.md) describes a managed gameplay core with no cartridge-reader/importer dependency, compiled mechanics, extracted presentation catalogs, a translated SPC sequencer/mixer, synthetic verification, private-ROM subsystem audits and resource/reachability audits. Its extraction boundary and source-address preservation are especially pertinent to this project's goal. Its [root reference list](https://github.com/MrJackSpade/SuperMetroidDecomp/blob/216f3a1d38c2e9d82ec9c0e626a35415b74d47c9/README.md) uses our same C pin and an older assembly pin (`362be646...`).

**Completeness evidence conflicts within the same revision.** The root README claims end-to-end playability with minor glitches. The developer guide calls itself the authoritative high-level summary but limits retained continuous play to awakened Parlor after Bomb Torizo and lists general room/FX/dispatcher gaps. The [replay parity document](https://github.com/MrJackSpade/SuperMetroidDecomp/blob/216f3a1d38c2e9d82ec9c0e626a35415b74d47c9/docs/smv-gameplay-parity.md) includes an earlier unresolved 100% replay divergence, then later reports **494,199 input-only updates across 513,793 source frames** passing for the "Samus drunk" movie and says Ridley, 100% and 13% movies continue to pass. Those later statements are significant author-reported evidence, but documentation drift prevents a simple completeness verdict. No local build, trace regeneration, CI-result review or independent playthrough was done here.

That parity document's policy explicitly excludes hardware lag, preserves authored waits/input edges, imports initial state once, and forbids subsequent reference-state injection. This is a useful model for the proposed semantic-vs-original-timing acceptance split. A passing selected movie is not universal behavior coverage.

The complete tracked-file inventory contains no root project `LICENSE` or equivalent copying grant. [D3D11 third-party notices](https://github.com/MrJackSpade/SuperMetroidDecomp/blob/216f3a1d38c2e9d82ec9c0e626a35415b74d47c9/csharp/D3D11_THIRD_PARTY_NOTICES.txt) cover named dependencies, not the whole port. Reference attribution to MIT upstream also does not license every new contribution. Read for design and diagnosis; establish permission before incorporating its original code. This limitation does not change the existing MIT C candidates' import suitability.
