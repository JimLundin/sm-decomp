- The assembly [`tools/rip_assets.py`](https://github.com/InsaneFirebat/sm_disassembly/blob/7af131ebc328359e852e923603163a329c7aa7af/tools/rip_assets.py) checks ROM identity before extracting. ## Two verified correctness gaps in upstream

1. **Remaining CPU fallback:** [`Bang_Main` at `$A3:BB25`](https://github.com/snesrev/sm/blob/578f90b3cc49557bb70060ad033bb90b8cf8ac50/src/sm_a3.c#L1635) calls `Call(E->bang_parameter_1 | 0xA30000)`. [`Call`](https://github.com/snesrev/sm/blob/578f90b3cc49557bb70060ad033bb90b8cf8ac50/src/sm_cpu_infra.c#L53) executes `RunAsmCode`. This is a specific untranslated native-to-65816 path, not just an unused declaration. The translation manifest needs to identify it and either preserve an explicit measured fallback or replace it with validated dispatch.
2. **The C frame oracle is normalized:** [`VerifySnapshotsEq`](https://github.com/snesrev/sm/blob/578f90b3cc49557bb70060ad033bb90b8cf8ac50/src/sm_cpu_infra.c#L469) copies dozens of RAM regions between snapshots before comparison. The same file installs ROM fixes and patches carry behavior; [`Vector_RESET_Async`](https://github.com/snesrev/sm/blob/578f90b3cc49557bb70060ad033bb90b8cf8ac50/src/sm_80.c#L153) explicitly removes the original four-frame wait. Consequently C-vs-C/Rust semantic equivalence and unmodified-ROM/TAS equivalence need separate gates. Do not require native C/Rust CPU registers, scratch RAM, instruction counts or original cycle positions to match as if they still represented the same CPU execution.

The rewrite's [rewriting tutorial](https://github.com/testyourmine/sm_rewrite/blob/523787384a7c912153883b21714f5edabf4e2406/docs/rewrite_example.md) is useful naming guidance but includes malformed example code (a decrementing `for (int i = 0; i < 6; --i)` and a stray brace). Agents should use compiled source and executable cases as their translation authority, not blindly execute tutorial snippets.

## What must exist before a translation agent loop

Community-source freshness policy: at session preparation, record current upstream refs for the selected repositories and check relevant open PRs and successor links. Use the latest canonical community data for general research, while retaining project-specific branches when reproducing their behavior. Freeze reviewed SHAs for each translation task so an upstream push cannot silently change its oracle. At task selection, cross-check the routine against newer fixes and the C# implementation; record disagreements and settle them with the original ROM. Do not automatically apply all upstream changes: platform work, lag removal, optimisations and ROM-hack changes can alter the intended behavior. A source refresh invalidates only the evidence whose inputs changed, under the new decomp contract.

These are recommendations derived from the verified source contracts above, not completed implementation:

1. **Pinned source registry:** upstream revision and license, original ROM address, C symbol, assembly label, target Rust module, direct dependencies and outstanding fallback for each task. Merge by original address because rewrite names differ. Keep data/scripts separate from CPU routines.
2. **Built executable oracle:** headless or deterministic C routine/frame entry points with state import/export and recorded build identities. Validate the C baseline itself against selected original-ROM cases before accepting its behavior.
3. **Rust state/hardware seam:** explicit little-endian and wrapping-width access, banked ROM pointers, alias-safe WRAM views, I/O operations and resumable frame/coroutine state. C globals and pointer casts cannot be translated as independent owned Rust fields without handling overlap.
4. **Two acceptance contracts:** C-to-Rust observable semantic equivalence for each port, plus selected original-ROM gameplay/video/TAS checks. Record every comparison normalization and upstream bug fix rather than inheriting silent exclusions.
5. **Bounded task pack and runner:** one routine or tightly coupled subsystem, its source/dependencies, input snapshots, expected writes/returns/I/O, regression cases and a deterministic pass/fail command. Retry from the same snapshot, measure native and fallback coverage, and promote only passing source changes.

A good first algorithm candidate is [`DecompressToMem` at `$80:B119`](https://github.com/snesrev/sm/blob/578f90b3cc49557bb70060ad033bb90b8cf8ac50/src/sm_80.c#L2488): known C code, identifiable original address, bounded input/output and representative real compressed streams available from local extraction. Its test contract must also capture any documented RAM side effects, bounds and address mapping. Passing that pilot would prove the source-to-Rust loop before tackling NMI, door transitions or the full Samus movement subsystem.
