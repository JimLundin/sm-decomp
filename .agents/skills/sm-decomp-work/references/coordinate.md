# Coordinator role

Keep the root available for user requests while an implementation overseer owns
the pipeline. Assign disjoint complete responsibilities, one file/lane owner and
one Git integrator. Overlap source, review, compilation and replay when their
dependencies and measured resource budgets permit.

- Give workers the short assignment in SKILL.md and their role. Link existing
  handoffs for exact pins; keep decisions and current host/resource policy in
  living PLAN/REVIEW. For fresh bounded workers, use fork_turns="none" when
  available and include the complete assignment and authority paths.
- Apply the latest direct user host/cache authorization over older plan wording.
  Execute only on authorized hosts; a stopped host resumes only on explicit user
  restart. Host assignment schedules work; the accepted architecture stays portable.
  Use authorized compiler caching and experiments under the same resource ledger.
- The root owns one machine resource ledger. Sample actual RAM, CPU, paging and
  disk before admission. Count launchers/descendants, admitted jobs' remaining
  growth once, copies, captures and retained outputs; maintain PLAN's reserves.
  Preserve existing live jobs and frozen inputs. Release terminal admissions
  promptly, and increase concurrency only when measurements support useful throughput.
  On a reserve breach, stop the newest producer per PLAN and retain lightweight
  readers. Record uncertainty when continuous measurements are unavailable.
- Inspect exact execution and agent handles before recovery. Recover or reassign
  only from authoritative terminal/missing handles; observation timeouts and stale
  files/comments do not establish termination. Carry forward pinned results.
  With collaboration tools, followup_task activates terminal workers;
  send_message alone does not. Refill ready work before inventory/report prose.
  User-authorized support watches the coordinator's actual handle and resumes
  the same session or one replacement only after verified failure, preserving
  the integrator, live jobs and frozen sources.
- Integrate the reviewed, qualified final pin. Fetch/reconcile remote state,
  preserve concurrent edits, run PLAN's local rows and progress command, then
  publish frequent small coherent code-bearing commits promptly with measured
  Score last. Follow current user branch/landing authorization; temporary
  isolation may protect main, with branch-only/unverified status explicit.
  Qualified publication needs no documentation/planning ACK and should not wait
  for prose or unrelated research. README progress images, treemaps and Pages
  publishing are retired; none is a completion step.
- Periodically dispatch a bounded process-improvement worker on necessary work:
  measure the source/review/build/capture/replay/landing bottleneck, make one change
  or experiment, then compare useful throughput and resource costs. Preserve
  accepted proofs by exact hashes; repeat checks only for changed dependencies or
  a new concern. Claim speedup only from comparable measured evidence.
- Separate net engine changes from verification/support costs and count all
  retained owners, adapters and dependencies once. Keep full portable owned
  Session, independent rendering/audio/backend, boot-to-credits fidelity, Map Rando
  and PLAN/REVIEW's size goals open until the destination validation is satisfied.
- For authorized GitHub mailbox assignments/handoffs, follow issue #2's Markdown
  communication directive: owner, result, next action and actual blocker, with
  spaced numbers/words and raw transport in details. Route user-facing #6 facts
  through the root to its sole communication representative.

An executor handoff or paused observation is not project completion. Name the
next owner, exact pin/handle and unfinished work before ending a role; route new
user requests without abandoning the active implementation objective.
