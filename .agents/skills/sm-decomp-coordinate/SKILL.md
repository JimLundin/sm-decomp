# Coordinate core work

Read [PLAN](../../../docs/PLAN.md) first, then [REVIEW](../../../docs/REVIEW.md)'s
Milestone plan at each item's start. Phase 0 verification-loop work lands first;
its exit is two consecutive green scheduled full-corpus runs. REVIEW sets the
active phase; PLAN owns checks, resources, Git and completion. User instructions win.

Before assigning ownership, interfaces or backend changes, read the
[destination](../../../docs/target-architecture/README.md) and its Windows policy.
One primary owns integration, the sole Git writer and one resource ledger.
Primary transfer needs explicit release and authoritative terminal writer/turn
evidence; carry live jobs, source pins and reservations. Preserve retired writers'
release; recovery targets the current primary.

- Delegate ready core source/review/build/replay to bounded workers with disjoint
  files and fixed interfaces. Refill when dependencies and ledger fit; continue
  implementation/handoffs during CI. Choose concurrency by useful throughput.
- Choose core items by the active REVIEW phase. Architectural progress is behavior
  crossing into target packages that compile independently of compat; preserve
  physical, mapped-retained and adjusted counts when measuring it. During Phase 0,
  keep complete persisted-layout compatibility and actual source/native/input proof
  as separate handoff identities, with genuine captures and no header restamps.
- Assign the objective skill with item/owner, repository, checkout/base/source pin,
  disjoint files/stages, rows, original handles and next recipient. Grant the ready
  sequence upfront through [resources](../sm-decomp-resources/SKILL.md). A fresh
  fork_turns="none" worker needs the complete assignment and authority paths.
- Inspect exact execution/session/goal/turn handles before recovery or reporting.
  Delivery, stale receipts and timeouts prove neither activation nor termination.
  Read successor receipts by bounded shallow inventory; preserve cursors, pins and
  timing/dependencies. Label unknown handles and keep audits off recovery monitors.
- Prepare successor executable commands/helpers, environment and pinned I/O paths
  before upstream EXIT. READY names those prepared inputs and unavailable
  dependencies. Assign next source/review/build recipients before READY. The
  primary alone activates terminal core handoff owners with followup_task for
  new explicit objectives; send minimal results before receipts.
  Drain ready code at the next safe source/Git boundary before bookkeeping;
  transfer accepted proofs only for unchanged relevant inputs.
- Recover/reassign only after authoritative terminal/missing handles. If tools
  cannot resume an authoritatively blocked external root, preserve live jobs and
  frozen source and reassign only already released scope to an activated owner.
  User-authorized support resumes the current primary or one replacement only
  after verified failure. Linux stays stopped until explicit user restart.
- Use direct session handoffs and durable repository/owned-artifact receipts.
  Task issues are retired; only [Jim's conversation #6](https://github.com/JimLundin/sm-decomp/issues/6)
  remains open for remote feedback. The primary reads/answers it at work boundaries.
  Update the sole report in #6's issue body daily under REVIEW.
  Direct handoffs stay concise: owner/result/next action/blocker; raw source and
  qualification proof remains in owned records.
