# Coordinate core work

Read [PLAN](../../../docs/PLAN.md) first, then [REVIEW](../../../docs/REVIEW.md)'s
Milestone plan at each item's start. Direct user instructions win. REVIEW sets
priorities; PLAN owns required checks, resources, Git and completion.

Before assigning ownership, interfaces or backend changes, read the
[destination](../../../docs/target-architecture/README.md) and its Windows policy.
One primary owns integration, the sole Git writer and one resource ledger.
Primary transfer needs explicit release and authoritative terminal writer/turn
evidence; carry live jobs, source pins and reservations. Preserve retired writers'
release; recovery targets the current primary.

- Delegate ready core source implementation, build and replay scopes, plus required
  review, to bounded workers with disjoint files and fixed interfaces. Keep released
  owners supplied when dependencies and measured budgets permit. Continue useful
  implementation and direct handoffs while CI runs; choose concurrency from the
  ledger and useful throughput.
- Assign the specific objective skill directly. Include item/owner, authoritative
  repository, checkout/base/source pin, allowed files or stages, rows, allowance,
  existing handles and next recipient. For a fresh bounded worker, fork_turns="none"
  is useful only with the complete assignment and authority paths.
- Inspect exact execution/session/goal/turn handles before recovery or reporting.
  An issue delivery, stale receipt or timeout is not activation/termination.
  Discover successor result paths with bounded shallow inventory; read the newest
  exact receipt and preserve event cursors, pins and timing/dependency attribution.
  Keep unrelated audits off the recovery monitor and label unknown handles.
- Drain READY code at the next safe source/Git boundary before bookkeeping.
  followup_task activates terminal workers; send_message alone does not. Promptly
  give released core owners their next scoped assignment. Transfer accepted proofs
  only for unchanged relevant inputs; send minimal results before long receipts.
- Recover/reassign only after authoritative terminal/missing handles. If tools
  cannot resume an authoritatively blocked external root, preserve live jobs and
  frozen source and reassign only already released scope to an activated owner.
  User-authorized support resumes the current primary or one replacement only
  after verified failure. Linux stays stopped until explicit user restart.
- Use direct session handoffs and durable repository/owned-artifact receipts.
  Task issues are retired; only [Jim's conversation #6](https://github.com/JimLundin/sm-decomp/issues/6)
  remains open for remote feedback. The primary reads/answers it at work boundaries.
  Follow [#2's Markdown directive](https://github.com/JimLundin/sm-decomp/issues/2#issuecomment-6445792069):
  owner, result, next action, blocker; spaced numbers/words and raw transport in details.

Route extra user requests without abandoning active implementation. Before a role
ends, name the next owner, exact pin/handle and unfinished work. Full owned Session,
independent rendering/audio/backend, boot-to-credits fidelity, Map Rando and size
goals remain open until [destination validation](../../../docs/target-architecture/VALIDATION.md) passes.
