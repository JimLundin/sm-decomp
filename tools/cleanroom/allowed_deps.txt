# The registry crates a clean crate may depend on (MODEL §1 decision 12). code_check.sh refuses
# any other registry, git or out-of-tree dependency, and on a listed one any key but `version`,
# `features`, `default-features` and `package`.
#
# The policy: a crate is listed when it is widely used and the standard choice for its job, std
# doesn't cover that job, it helps model the domain, and it builds on the development machine
# (a build script is baked in by tools/vendor_nobuild.sh and patched in the root Cargo.toml).
# The root approves each line; an implementer may ask for a crate in its report.
#
# Columns: package; the exact version requirement the Cargo.toml must carry; the dependency kinds
# allowed (normal, dev, comma-separated); the features `features = [...]` may switch on beyond
# the crate's defaults (comma-separated, `-` for none). `default-features` may take either value.
