# 03: Prepare and accept one supported routine/width increment

**What to build:** Take one measured selection through candidate preparation, execution coverage, focused comparison and full cold acceptance. A successful routine/width expansion advances the accepted state with demonstrated compiled execution gain; an invalid or uncovered candidate remains preserved for diagnosis.

**Blocked by:** 02: Select a measured routine/width increment.

**Status:** ready-for-agent

- [ ] Preserve the verified accepted snapshot and unrelated user edits, allocate evidence before mutation, and prepare exactly one selected routine/width slice using existing timed support. Bind selection, candidate source/config, generated artifacts and binaries to the run.
- [ ] Regenerate resumable compiled steps and build through existing machinery. Preserve build failures as errors with stage logs; whole-subroutine untimed output cannot provide cycle evidence.
- [ ] Require every newly enabled address/MX key and affected existing body key to execute in cold acceptance. Remove unexecuted proposed keys from the actual generated table and record them as deferred inventory, then regenerate and revalidate the resulting candidate; editing only the required-coverage list cannot satisfy the gate.
- [ ] Retain legacy unexecuted baseline keys as explicitly unvalidated inventory. Existing generated execution or execution by a different width key cannot establish coverage for a new key.
- [ ] Choose covered focused intervals for all changed keys and relevant boundaries. Run instruction/bus comparison even when frame parity passes, using paired checkpoints validated against cold execution and recording cache creation separately from warm replay.
- [ ] Require candidate check/lint and relevant regressions plus fresh generated/reference cold parity for all 18,000 any% input frames, comparing CPU/clocks, complete WRAM and framebuffer. Reuse independent synchronization, fallback or checks only with verified unchanged dependencies; shared changes require refreshed affected gates.
- [ ] Require positive observed generated-instruction gain under identical ROM/movie/profile/reset/seed/input interval. Report generated/interpreted totals and fraction, per-key counts, validated distinct keys, comparable deltas and deferred/unsupported inventory separately from call-target discovery.
- [ ] Finalize and atomically advance the local accepted pointer only after every mandatory gate passes and the predecessor remains current. Divergence, uncovered execution, infrastructure failure, incomplete scope and timeouts preserve the predecessor and failed candidate.
- [ ] Expose a reproducible one-increment validation outcome through repository commands and a linked brief, with meaningful coverage/acceptance rejection cases. Report the 60-second warm and 20-minute per-cold-replay targets without weakening gates on overruns.
