# Trace and frame storage format research

Status: resolved research question; implementation not started.

Examined baseline: `8bbef1f`, worktree `/tmp/sm-trace-storage-study`, 2026-10-11. This note uses repository source and official format specifications. Compression ratios and timings belong in the separate empirical study; none are inferred from the format documentation or from another worktree's spec.

## Recommendation

Use a versioned, lossless artifact container with **ordered binary event chunks compressed independently with Zstandard**, a game-frame/event index, and **byte-exact snapshot records with independently compressed full states initially**. Evaluate page references or bounded delta chains for repeated snapshots after measuring whether independent compression already makes them small. Keep JSON manifests and verdicts for inspection. Export the current text formats through a decoder so existing diagnostics remain usable.

This is an engineering recommendation from the access pattern below, not a claim that a custom binary format must beat every alternative. First benchmark raw text plus Zstandard against the existing gzip option: compression may provide most of the benefit without changing event representation. Choose a binary schema only if measured size, decode speed, or querying justify that extra contract. Zstandard's specification supports independent frames and concatenated decoding; its seekable extension adds byte-range lookup. Neither defines the game-specific records or frame semantics. [S1][S2]

## Proposed container contract

The following is a proposed project schema, not part of the Zstandard specification.

1. A small header identifies format/schema version, observation profile, source serializer identity, ROM/input hashes, producer identity, controller convention, and whether the stream records native semantic events or CPU events. Use explicit fixed-width little-endian fields; never dump a C/Rust struct with ABI padding.
2. Events retain a monotonically increasing **u64 sequence number** or an equivalent chunk-start sequence plus record ordinal. Encode event kind as a stable schema tag, preserving address/value widths, value presence, PPU selector and all callback arguments/results. Derive tags from a versioned table, not discovery order. Preserve the global observed order; if streams are split, a common sequence permits exact reconstruction. Text output can be reconstructed only when its original formatting profile is specified; otherwise preserve a hash of canonical typed events as a new identity.
3. Chunk by complete frames until a bounded uncompressed target is reached. Experiment with approximately 1–4 MiB chunks; that range is a benchmark parameter, not a sourced optimum. A single busy game frame may span several chunks. Index each frame to its first sequence/chunk and event span, including frames with no events. Store explicit epoch/run IDs, zero-based input index, hardware frame counter where observed, and pre-/post-frame boundary convention. Do not assume all existing `frame` labels mean the same thing: the port increments after `RtlRunFrame`, whereas reference replay can use an lsnes label adapted from scanline. [tools/port_live.py:607](/tmp/sm-trace-storage-study/tools/port_live.py:607), [crates/snes/src/bin/reference-replay.rs:60](/tmp/sm-trace-storage-study/crates/snes/src/bin/reference-replay.rs:60).
4. Each compression chunk is an independent Zstandard frame. Its project index records compressed offset/length, decoded length, starting sequence and event count, plus decoded payload digest. Independence permits bounded memory decoding and limits the amount read to inspect one divergence. Standard seekable Zstandard is an option for the byte-offset index, but its seek table records compressed/decompressed **byte sizes**, not game-frame IDs. A separate domain index is still necessary. [S1, Frames][S2, Seek Table Entries]
5. Store snapshot entries under the original artifact identifier, serializer/layout identity, exact decoded length and SHA-256 of the complete reconstructed bytes. Initially use an independent compressed full state. For dense repeated captures, benchmark fixed-size content-addressed pages (for example 4 KiB, also only a tuning parameter), or XOR/changed-page deltas against a full state at each group start. Never change snapshot cadence as part of a storage-only migration. A delta must bind the base-state digest, target length and target digest; cap the dependency depth and insert new full states when compression would be cheaper than a delta. Preserve framebuffer channels, padding and every existing opaque serializer byte.
6. Content-addressed pages may share identical bytes across states/runs, but a sealed artifact must declare and authenticate its complete dependency set. Snapshot digest refers to reconstructed state bytes, not the page manifest. Garbage collection follows reachability from retained manifests, and must not break historical acceptance evidence. Existing cleanup deliberately shares only authenticated immutable bytes: [tools/port_cleanup.py:112](/tmp/sm-trace-storage-study/tools/port_cleanup.py:112).

For the first prototype, independent Zstandard full snapshots are lower complexity than a page store. Sparse 1000-frame captures may have little temporal locality, while routine before/after WRAM captures may have much more; the repository captures both, so one delta policy should not be assumed optimal. [tools/port_live.py:586](/tmp/sm-trace-storage-study/tools/port_live.py:586), [tools/port_live.py:609](/tmp/sm-trace-storage-study/tools/port_live.py:609).

## Integrity, completion and determinism

- **Separate logical identity from storage identity.** Retain a SHA-256 of actual compressed/container bytes for artifact integrity and a separately named SHA-256 of canonical decoded records or original snapshot bytes for equivalence. Include schema/version, field presence, lengths, stream identity and record counts in the new canonical encoding so boundaries are unambiguous. Migration should verify byte-identical export for existing text and exact reconstructed snapshot SHA-256 before considering retirement of any original. Repacking changes physical identity even when logical evidence is preserved. This is necessary because current acceptance seals the physical files, and historical plain/compressed seals already remain distinct. [tools/port_live.py:182](/tmp/sm-trace-storage-study/tools/port_live.py:182).
- **Compression is lossless without promising identical compressed bytes.** Pin codec implementation/version, parameters, dictionary bytes, chunk boundaries, thread settings and flush behavior if reproducible packed files are desired. Version alone is insufficient: the official header documents that prefix compression can produce different results depending on whether prefix and input buffers are adjacent. Its determinism setting is experimental, so avoid prefix dependence in the simple format, or explicitly account for it. Logical equality should survive a codec upgrade without pretending the upgraded physical seal is the old one. [S3, `ZSTD_c_deterministicRefPrefix` and compression parameters]
- **Checksums are not evidence seals.** Zstandard's optional content checksum and seekable entry checksum are the low 32 bits of XXH64 over decoded bytes. They help detect accidental corruption but cannot substitute for the project's SHA-256 artifact identities. The base format also permits a decoder to ignore checksums, so the project reader must actively require and verify its own declared integrity fields. [S1, Compliance and Content Checksum][S2, Checksum]
- **Reject truncated complete chunks as well as truncated records.** Truncation inside a compressed frame can be reported by a conforming decoder, but a concatenation ending exactly after a complete earlier frame remains a syntactically valid shorter Zstandard stream. Require an authenticated final completion record with expected frame/event/snapshot/chunk counts and overall logical digest. Validate full consumption, record lengths, exact decoded chunk sizes, sequence continuity, index coverage, and absence of unexplained trailing data. An interrupted file may expose a recoverable prefix for diagnosis, but cannot be accepted as complete evidence merely because it decompresses. This requirement follows from independent concatenated frames and the seek table's placement at the end. [S1, Frames][S2, Format and Seek Table Footer]
- **Avoid silent overflow.** The official seekable format uses u32 frame count and u32 compressed/decompressed sizes; cumulative offsets are sums and require checked wider arithmetic. Bound each chunk below those limits and check seek-table-size arithmetic, or use a versioned u64 project index. Game-frame IDs, event sequences, byte offsets, total lengths and counts should use checked u64 arithmetic. Reject oversize declared lengths before allocation and malformed/overflowing varints. Wider container fields cannot repair a counter that already wrapped in an observer; preserving the original observed label and a separate monotonic sequence/epoch is necessary. [S2, Seek Table Footer and Entries][tools/port_live.py:592](/tmp/sm-trace-storage-study/tools/port_live.py:592).

## Alternatives

| Format | Primary-source capabilities | Assessment for this repository |
| --- | --- | --- |
| Plain text + gzip | Gzip is lossless streaming storage; the RFC explicitly excludes random access. It has CRC32, 32-bit modulo input size, and optional time metadata. [S4, 1.1 and 2.3.1] | Already supported; useful immediate baseline. A giant member requires decoding its preceding data to reach an arbitrary event unless an additional index/checkpoint scheme is implemented. Do not infer observed savings without measurement. |
| Plain text + independent Zstandard chunks | Frames decode independently; standard concatenation retains decoded order, and seekable format supplies compressed/decompressed byte lengths. [S1][S2] | Best low-risk first benchmark. Keeps current observer output and adds compression and bounded retrieval before a binary schema is necessary. |
| Binary events + Zstandard chunks | Zstandard compresses arbitrary bytes and permits user metadata through skippable frames. [S1, Frames and Skippable Frames] | Recommended eventual canonical event artifact if benchmarks justify typed records. Compact integer fields eliminate repeated formatting, while a domain index supports first-divergence inspection. That size advantage is a hypothesis until benchmarked against compressed text. |
| Arrow IPC | Arrow specifies typed columnar memory/transport, dictionary arrays, record batches, file/stream layouts and per-buffer LZ4/Zstandard compression. [S5, Arrow Columnar Format, Compression, IPC File Format] | Credible standardized option if vectorized analysis or cross-language consumers are the primary requirement. It can preserve rows, but requires a project event schema and explicit sequence/frame semantics. It does not automatically deduplicate snapshots or preserve original formatted hashes. Consider as analysis export or a competing benchmark, not dismiss it as uncompressed. |
| Parquet | Columnar storage with row groups, column chunks, per-column encoding/compression and footer metadata that readers inspect before data. [S6, Concepts, File Format, Data Pages] | Strong for querying selected fields across many runs. Requires explicit event ordinal and `ORDER BY` when queried; opaque snapshots still need a separate exact-byte design. Useful analytical derivative; footer dependence and columnar machinery add work for an append-only, fail-fast verifier. No claim that Parquet cannot preserve ordered rows. |
| SQLite | Official guidance supports application file formats and archive/data-container use, including incremental and atomic updates. Query order without `ORDER BY` is undefined. [S7][S8] | Credible manifest/catalog and random-access container, especially if query flexibility matters. Use explicit event sequence and compressed chunk/page blobs if evaluated; row-per-event SQL storage is a separate benchmark and does not inherently exploit temporal snapshot redundancy. No unsupported claim that SQLite must be larger or slower. |
