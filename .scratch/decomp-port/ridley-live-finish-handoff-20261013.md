## Strategy diagnosis

The work has advanced source translation substantially, but we spend most time
reconstructing acceptance contracts and transporting evidence rather than
translating new gameplay. The lexical routine count and live-exercised count
measure different stages and should not be reported as one completion estimate.

This lane's measured costs: cold release pipeline build241s; r7 replay about230s
for four subjects plus a long single-thread debug SHA256 pass over four1.5GiB raw
effect logs; controlled whole fixtures materialize about3GiB for6457pairs;
native137 waits on the same worker leases, then emits about815MiB for1840pairs.
Fresh exact-source contexts prevent reusing current-source acceptance even when
some dependencies only changed observers or formatting. Recovered crashed
owners also repeatedly rebuilt probes whose generated templates lagged source.

A stronger strategy would freeze gameplay module/source interfaces earlier,
give whole subsystems one reusable typed transaction/hardware/observer ABI, and
derive affected-family fingerprints from semantic compiler inputs rather than
large unrelated harness files. Maintain meaningful differential fixture coverage,
but run fast deterministic compiled seam checks and packed boundary replays
before full movies. Produce incremental packed evidence at capture time; avoid
raw multi-GiB debug logs and rehashing four duplicate artifacts serially. One
deliberate full integration gate per source freeze can replace repeated broad
gates while keeping exact source and four-process independence.

No exemption or acceptance weakening was applied. The pending whole live gate
still needs full129712 parity, zero CPU fallback, native137 nine-ID/allocation

header/area/window/timer/frozen/material counters. Current whole admission checks
